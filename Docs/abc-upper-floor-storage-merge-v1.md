# 收納併入主3D前的同版核對

2026-11-11。[收納顯示驗收](abc-upper-floor-storage-3d-qa-v1.md)完成後，先逐層比對收納來源與[目前整棟3D](../structured/candidates/kaohsiung-house-options-3d.html)內嵌的實際樓層資料。[機器核對與未套用座標](../structured/coordination/upper-floor-storage-merge-review-v1/review.json)包含十個收納版本、30組棟層／使用狀態對照，沒有啟動場景或修改已驗收檔案。

## 整合順序

| 範圍 | 比對結果 | 接下來怎麼做 |
| --- | --- | --- |
| A 2F／3F／RF | 六個A／C案例中的三個，完整房界、家具、門前及機電預留與收納來源相符 | 可先作同版加櫃比較；只新增三件獨立雜物櫃，不抵扣原衣櫃，A裝潢仍交另聘設計師核對 |
| C 2F／3F／RF | 與c-split實際樓層相符，含已整合樓梯版本的上下文 | 可先作同版加櫃比較；保持唯一2F洗衣機，C3共用取物需進主臥的代價不省略 |
| B 2F | 收納用P4；舊3D沒有同一個quiet-living房界 | 先整層接P4房界、器具及排水／乾背區，再加櫃，不能只把目標房名換成living2 |
| B 3F | 收納用Q3，舊3D仍是較早房界與上層梯 | 先連Q3 L形KTV、乾背區及新梯核建立同版場景，不能只把櫃子加到quiet-study |
| B RF D1／D2 | 各用Q3屋頂到達、門路、設備及自己的折衣檯位置，與舊3D不同版 | 兩版分開接新梯／平台及設備；各把原桌改下櫃工作檯，不同時畫舊桌與新櫃 |

六筆A／C未套用的新增物件座標已記錄實際host room ID、全層與房內相對位置、長深高、操作帶、原樓層hash及必須保留的家具ID。這些是後續加櫃的核對依據，尚未生成或驗收新的主3D。

## 為什麼B不能照座標直接加回去

B四個收納案例的櫃體在舊圖相同XY處也會落在一個房間內，重疊面積都是櫃體本身的0.54㎡。但這只說明該點在舊房間內；P4／Q3的完整房界、樓梯、設備及來源房名均不等同舊圖。若只核「放得下」，畫面會看似成立，實際仍混用不同版設計。

所以兩種一樓入口各自的daily／ritual／carry狀態都分開核，不能拿後門案的樓層替前門案默認背書。後門仍為預設、前門為無後巷備案；B神桌朝街與正前方門、乾背保護、前後搬轎目標及RF24㎡缺口均保留。比對不同版不表示新櫃提案失敗，也不表示B已無法設計。

## 本輪的完成邊界

- 已完成：A／C六層同源核對與未套用加櫃座標；B四版與兩入口各三態的差異確認，指出整層同步順序。
- 原主3D、已驗收儲藏檢視與ZIP、平面及149項保留控制均未改；不需重跑原儲藏檢視的同一份驗收。
- 尚待：A／C新增物件後的整層與單房畫面核對，及B整層多邊形／梯核／屋頂同版整合。完整主3D重建與瀏覽器驗收仍分流到屋主另一終端機。
- 實際門片掃掠、展床、搬入取物、固定防水、容量、風水與專業核可仍待對應條件，不能用同源座標取代。
