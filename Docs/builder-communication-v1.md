## 建議怎麼談，才不會一直重講

第一次只帶「第一次會議」與本次ABC比較圖，先確認合作範圍、基地可建量、A設計師介入時間、討論版次與報價方式。不要把所有歷史方案或184欄新風資料一次交給對方。圖面是生活目標與比較參考，不是施工依據；約32地坪還要核騎樓、退縮、牆柱與管井。

| 階段 | 先談到什麼程度 | 要帶走的回覆 |
| --- | --- | --- |
| S01 首次接洽 | 基地與合作範圍、窗口、A另談裝潢、怎麼估價 | 待件清單、責任草表、負責人與回覆時間 |
| S02 初步格局 | 同版牆柱／樓梯／濕區／開口、各棟生活需求 | 淨面積、剖面及未解衝突的完整替代案 |
| S03 預埋前聯席 | A設計師與建商／機電一起核完成面、降板、管路、天花和檢修 | 同版合圖、逐項界面及最後決定日期 |
| S04 發包採購前 | 標配、折抵、追加、另包與替代品 | 同範圍完整報價、圖面版次、工期與保固介面 |
| S05 隱蔽工程前 | 埋管／灌漿、防水覆蓋、天花封板各自安排檢查 | 定位照片、試驗、缺失與覆查，按約定處理工項 |
| S06 交屋及裝潢銜接 | 調試、竣工圖、維護教學；A進場現況與保固 | 完整設備／測試資料、缺失清單、A交接與修復窗口 |

階段是議題順序，不是規定所有工程都等到同一天才決定。開口、降板、排水及結構等不可逆工序，要依實際排程提前；S02～S04可反覆比對。資料尚未進來時，先留欄位、提供人與回覆期限，並先做其他不依賴該資料的準備。

影響管距、降板、電源或補強的產品，在相應預埋前就要有同版安裝尺寸，或由專業確認可替換產品的範圍；不能等S04報完價才發現S03已施工的介面不合。

每次會議結束前，由屋主核對紀錄是否符合自己的理解，再依各方約定確認。下一次從「未解項與新回覆」開始，不重談已記錄且未受變更影響的事項。

## A棟現在就要留的介面

獨立的[a-interface-matrix.csv](../structured/planning/builder-communication/a-interface-matrix.csv)列11項：承作範圍、格局與門窗、濕區防水排水、冷氣新風天花、電力照明、MDF弱電、照護門組、櫃體固定補強、選品折抵、隱蔽檢修，以及點交保固。每列已有建議提供資料與共同核對事項；真正設計、供料、施工、測試及保固方全部留待議定。

A設計師若尚未委任，建商先提供梁柱、完成面、管道及工序日期，列哪些可延後、哪些要保留、最後何時必須決定。不能把「以後裝潢再做」當成已解決，尤其是樓板降板、排水、牆內補強與穿梁開孔。室內風格、櫃色及軟裝可另談，影響建築與預埋的部分要早交接。

## 回覆、估價、變更都用同一個ID接起來

本包提供七份CSV空白範本：

| 檔案 | 用途 |
| --- | --- |
| builder-replies.csv | 22題的回覆、證據、提供人、期限；屋主選擇、專業審查及施工圖發行分欄 |
| a-interface-matrix.csv | 11項A介面的資料與實際分工／期限／保固約定 |
| same-scope-quotes.csv | 12組估價範圍，填完整方案、含項／不含項、折抵、工資配件、稅金、保固與工期 |
| meeting-decisions.csv | 每次會議的結論、未解題及下一步；記對應問題／介面ID |
| change-log.csv | 原新作法、代價、受影響功能／上下層與圖面，誰選擇／誰審查／何時發行 |
| inspection-log.csv | 按工序記錄通知、測試依據、照片、缺失與覆查 |
| drawing-register.csv | 記棟別／樓層／方案／狀態／圖號／版次與舊版停用，避免拿錯圖 |

例如BC-13的天花管路回覆若影響A設計師，會議紀錄寫BC-13及A-IF-04；若要改圖，再另建變更ID，列費用與受影響版次。對方說「可以做」、屋主選擇、專業核對及施工圖發行各自有欄位，不會因一格回覆就把全案視為採用。

空白就是尚未紀錄，不等於零元、不需要、已含或通過。可在回覆狀態填「尚未詢問／已答待核／需補資料／需屋主取捨」等文字；實際簽認方式依約定，CSV本身不產生契約效力。B前後完整案、新風替代系統或重複設備候選分開估，不全部相加。一般衛浴保留易清潔包覆外形偏好，歷史候選價格採購前重核。

## 建立可填寫的私人工作副本

公開structured下的是可再生成的模板，**不要直接填在公開模板上**。在WSL專案根目錄先建立全新目錄；以下指令不需實測資料、不聯絡外部，也不修改需求或圖面：

```bash
timeout 20s env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/export_builder_communication.py --init-records inputs/private/builder-meetings-001
```

產生七份可填CSV、RECORDS.md與不可覆寫的當次基準basis-review.json；已有同名目錄就拒絕，下一套改用002。私人目錄不進Git，請自行備份。工具不讀取填完的回覆、不自動採用或套圖；需要採用、重算及正式交付時，仍走[現行條件式流程](abc-conditional-planning-v1.md)與[正式圖面版次](review-workflow.md)。R001舊交付包保留，真正交件另建新版本。

Windows可開：`\\wsl.localhost\Ubuntu\root\workspace\houseDesignPrepare\inputs\private\builder-meetings-001`。要給建商或A設計師時，只複製本次必需的文件，不附私人預算或全部歷史目錄。

議程唯一輸入為inputs/builder-communication-plan.json；原work_item、requirement及register只引用，不回寫。靜態產物帶來源與產物雜湊，來源改動須重產本包，不能借用先前passed。這是文件、表格與檔案檢查，不是新3D、瀏覽器目視或專業簽認。

```bash
timeout 20s env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/export_project_next_steps.py
timeout 20s env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/export_builder_communication.py
timeout 20s env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/export_builder_communication.py --check
timeout 20s env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B -m pytest -q -p no:cacheprovider tests/test_builder_communication.py
```

先更新總表、再更新引用它的溝通包。兩個生成器只產小型獨立文件，沒有整套場景重建；不啟動瀏覽器、WebGL、全套pytest或外部AI。現在未要求你補基地、立即選方案或委任廠商。
