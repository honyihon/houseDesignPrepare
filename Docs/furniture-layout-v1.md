# HTML／3D 共用家具配置

目前展示 ABC v2 有界合理性提案。HTML 共用圖、逐房清單與 `structured/candidates/model3d.html` 使用同一份房間、家具中心、旋轉、門位、樓梯和冷氣配對；不是可建容量、採購清單或施工定位。改版取捨見 [ABC 合理性提案](abc-layout-rationality-v2.md)。

## 本版範圍

- 3 棟、12 層，105 個提案空間；61 個家具空間、129 件家具／設備，另有 17 組冷氣配對（不算家具件數）。A 一樓已回補孝親房與淋浴；主案車位另案、給水併入工作陽台，玄關收納移至前帶客餐廳，因此空間數下降但不是再刪孝親需求。B 3F 露台原室內沙發床與瑜伽墊仍為替代案。原 HTML 92 個來源格位的原始尺寸保留。
- [C 一樓續版](c-1f-space-use-v3.md)：獨立四人餐區、180cm雙人沙發正對TV、90cm單椅、120cm孝親房衣櫃與240×60cm廚具候選；原三人沙發、六人桌、240×65cm廚具及360cm衣櫃未容納，換品不當原要求完成。前院虛框不計家具。
- 採常見市售代表尺寸，不宣稱統計平均、选定型號或實測。重新選用 120cm 衣櫃、152 × 188cm 床、43吋壁掛電視等會明列為替代型，不把原型號縮小。
- 固定比較框 6000 × 17630mm，不因家具增大而加深。這不是地籍、建築線、完成面外框或核准面積；前院、騎樓、陽台及屋突的適用性未知。
- 三棟 1F 的家具初排沒有程式偵測到的量體／預留帶衝突；樓上淨空續版把6件待調整降為2件（A 2F兩組180cm衣櫃）。A走道櫃操作與通行需分時，無衝突不等於完整動線、法規、照護或搬運合格。

## 查看方式

1. 開啟 `structured/candidates/model3d.html`；預設 A 棟 1F「全層需求導覽」。以 A／B／C 捷徑和樓層按鈕切換。
2. 在「全層需求導覽」取消「完整牆高」看家具形狀，或用「俯視（對 HTML）」核對配置；道路／前方在上方 `y=0`。不要切到原格位單房來驗證新提案。
3. 點房名、房間按鈕或家具看名稱、尺寸、依據；全層選房不隱藏其他房間。選房後用畫面上的「房間特寫」放大共同幾何、只顯示該房標籤，「返回整層」取消選房。特寫網址保存 `focus=room`，不另造單房空間。手機可收合控制後直接操作這兩個按鈕。
   特寫預設啟用「房間特寫自動剖視」：依相機方向裁去遮擋的牆、門窗框與梯段上部，留下約55cm高的展示邊界；旋轉會重新判斷，冷氣及家具本體不裁切。這不是拆牆或改樓梯，不改共用牆位、尺寸與擺位。勾「完整牆高」或取消自動剖視可核對未剖視畫面；返回整層後恢復原展示牆面。
4. 「樓梯 → 下一層」只切換展示，不證明實際梯段、淨高或屋突合法。
5. 開啟 A／B／C HTML 的 1F／2F／3F／RF，先看共用圖與編號清單。舊格子、坪數、系統位置與需求卡位於折疊的歷史對照；新提案房間連結用 `#proposal-room-<key>`。
6. 原格位單房／檢查只對照原 CSS／文字覆寫幾何，不是 ABC v2 全層提案；新增的走道與設備分區不混入原格位模式。

## 配置規則與未解項目

床頭、沙發背、衣櫃、廚具與衛浴優先靠實牆；活動家具可移位，尺寸不縮放。茶几跟隨沙發，電視對準床或座位。餐桌以桌椅外廓與拉椅空間檢查，不只看桌面。

距牆以牆軸 80mm 暫估（假設 100mm 牆厚，半厚加留量），不是完成面淨距。入口前 900mm、櫃門與設備操作帶都是討論預留，不是門扇掃掠、消防或無障礙標準。MDF 另保留後側 600mm 檢修；弱電櫃放梯廳側邊壁龕，不拿梯段或公共通道當機房。

目前未解家具：A 2F更衣前室兩組180 × 60 × 220cm衣櫃，會擋門口接近帶。原尺寸、原因保留在兩邊清單，正常圖不畫成已安裝；勾「顯示越界／碰撞家具」可看問題量體。未採用的中島、車位、收納、淋浴、完整客房另保留替代案，不因未顯示就算滿足。

`abc-rationality-v2-upstairs-clearance` 只重排樓上候選分界／門位／朝向：A公衛和更衣前室分界移200mm，外框分別為2400 × 2100mm、2000 × 2100mm；洗手台、馬桶與90cm淋浴維持市售外廓及700mm操作帶，馬桶與洗手台本體間暫留151.8mm，不是人體側向或無障礙核可。240 × 40cm走道櫃沿右牆，避開主臥／前室門口；兩側各暫扣80mm時，關櫃通行1040mm、600mm操作時僅剩440mm，取物時須暫停通行，若須連續救援通行應另移櫃體。

B公衛／套衛分界前移200mm，外框分別為3000 × 2000mm、3000 × 1830mm，總濕區與主臥外框不變；公衛60cm與套衛90cm洗手台、馬桶、90cm淋浴都保留，操作帶均700mm。A公衛與B套衛採滑門提案，完成面、門框／軌道、淋浴門、機械排風、排污、防水和救援尚待建築師／設備人員核對。A公衛不是原私用套衛、更衣前室不是已完成雙排櫃，B後段衛浴不是原中段濕核條件已通過；未改正式需求、實測或封存版次。

## 建築、照護、祭祀與空調

- 曬衣架使用開放式細桿造型，戶外椅使用椅腳／椅背條板，不共用機櫃或軟包沙發的量體；外廓尺寸不變。戶外適用材質、防雨、防颱、欄杆及設備遮蔽仍待產品與建築設計確認，造型不證明可露天安裝。
- C 1F 原 `sideyard` 格位在本提案是室內乾式 IDF 壁龕，明確標為非室外；不能沿用原側院屬性，把室內設備當作露天設備。
- 樓梯同軸，暫採 3m 層高、18 踢級、270mm 級深、1000mm 梯寬及平台的雙折梯，示意外廓 2200 × 4160mm。RF 只標到達平台與下樓梯井，不另假設第五層。完成面、扶手、梯井、淨高、結構及消防未核。
- 只提出前／後外側候選窗，不假設側界可開窗。神桌背面維持實牆；浴室暫採高窗。採光、換氣和合法開口未知，內部濕區需排風方案。
- C 孝親房暫留 1200mm 側邊路徑與 1500mm 轉位方框，非無障礙核可。醫療床、輪椅、照護者、倒地擋門和套衛門向需演練。
- A 孝親房外框 3600 × 3770mm，1520 × 1880mm 床、1200 × 600mm 衣櫃；90cm滑門、120cm路徑與150cm轉位均為提案。夜間如廁由公共乾區直達公衛，不經廚房或MDF；後工作陽台深1800mm、給水設備由廚房直達。主案不計車位，前帶可合法興建與原需求後帶客餐廳改前帶的取捨尚待核。
- A 公衛保留馬桶、洗手台、1200 × 1200mm零門檻淋浴提案；3D不畫成封閉玻璃淋浴間。浴廁操作與轉位地面、廚房操作與入口接近／通行帶可分時共用，明列 `shared_operation_with` 和限制，設備本體仍不得侵入暫留區。這不是已驗證無障礙或避難通道；開抽屜、冰箱或洗碗機時不可同時通行。
- B 武轎目前 1200 × 1700 × 1800mm 是規劃收納外廓，讀自 `inputs/physical-items.json`。1600mm 通道／1500mm 門只初篩收納本體；抬桿、搬運人員和雨天路徑未實測，不因此通過搬運檢核。
- 冷氣有配對編號、同層／跨層位置和高位折線配管估長。原廠機型、最短／最長管長、高低差、追加冷媒、散熱、排水、維修及更換路徑皆待核，不當安裝許可。
- 全層剖視保留室內機所在牆面的高牆；房間特寫可裁去遮擋部分，但室內／外機的定位與本體不改。地板材質、牆厚、門窗框與55cm展示剖高都不是裝潢或施工定案。

## 可編輯來源

`inputs/concept-layout-review.json`：比較框、優先順序、逐層矩形、相鄰開口、家具替代 profile、冷氣配對和替代需求。與實測檔分開，不寫回 `inputs/dimensions.json` 或正式需求狀態。

`scripts/lib/model3d_functions.py`：A 一樓功能回歸檢查。以明確 `requirement_id` 讀取原需求面積／門寬，不只檢查兩個前端一致；缺孝親房、床、衣櫃、淋浴、150cm轉位或公共如廁路徑會拒絕產圖。結果保持有條件初篩，原需求不會因此變 confirmed。

`inputs/furniture-layout.json`：

- `catalog`：代表家具名稱、外廓、類型、顏色。
- `profiles`：家具組合；提案覆寫時，原 assignment 保留為 `deferred_furniture_assignment`。
- `rooms`：歷史房間 id 与配置依據，不由新提案冒充原 HTML 承諾。
- `position`：0–1 偏好比例，不是解算後座標。
- `wall_anchor`、`wall_locked`：牆側、是否准許換牆。
- `wall_gap_mm`、`front_clearance_mm`、`rear_clearance_mm`：暫留距離；`mount_height_mm` 是壁掛底高。
- `in_front_of`、`front_gap_mm`、`aligned_with`：家具相對關係；缺目標或循環拒絕產圖。
- `shared_operation_with`：明列分時共用地面及限制，不縮小操作帶，也不允許設備本體侵入；只允許浴廁轉位及廚房工作／門口接近區的指定類型。
- `step_free`：僅供淋浴提案使用，代表無高門檻／固定玻璃圍隔的視覺意圖，不是施工與無障礙認證。
- 舊 `concept_min_depth_mm` 保留追溯，ABC v2 不以它放大房屋。

大型實物以 `physical_item_id` 引用 `inputs/physical-items.json`，不重複填尺寸。收納與組裝搬運實測仍分開，見 [實物登錄](physical-items.md)。

修改提案／家具後，一起更新 viewer、共用資料與 12 份 SVG：

```bash
.venv/bin/python scripts/export_model_3d.py
node scripts/check_windows_playwright.cjs --preflight
```

只有修改原 HTML 來源語意時才先跑 `extract_layout_data.py`、`build_room_program.py`。不要手改生成 SVG 或維護另一份百分比覆層。交付 HTML、`assets/`、`structured/` 要一起保存。

## 驗證邊界

Python／JS 測試比對共同幾何、同軸樓梯、冷氣配對、門洞與共用邊界，檢查越界及預留帶。`predesign consistency-review` 偵測過期資料／SVG。

Windows CLI 以實際瀏覽器檢查 12 層、連結、家具尺寸／位置、待調整狀態、主控制及手機標籤，截圖仍需人工目視。`--preflight` 不啟動瀏覽器，不是畫面 QA。舊版通過報告不可替本版背書。
特寫驗收另檢查設備本體的五個取樣視線、旋轉後遮擋更新、完整牆高／返回整層恢復，以及HTML／3D幾何和pending清單不變。取樣只查建築示意物遮擋，不是每個像素可見、其他家具不遮擋、通行或專業核定；新版仍待Windows重跑與截圖目視。

建築師 R001 到齊且通過匯入 preflight 後，須依基地、建築線、柱牆、完成面及法規重排，並確認屋主取捨；不能直接將討論模型轉作施工圖。
