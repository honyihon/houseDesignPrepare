## 執行與狀態

此稿已準備，但編寫時本環境對 Ollama 本機 socket 與 Windows 互通皆被拒絕，插件搜尋未找到可用的 Ollama 連線。**尚未取得 Kimi 回覆，沒有兩模型討論結論。**

屋主確認目前 Ollama 裝在 WSL，版本 0.20.3，`ollama list` 為空。本機清單空白不表示雲端模型不存在；先前 `house-c1f-kimi-LYQZFe` 是舊腳本的本機清單門檻擋下，沒有送出 `/api/chat`，不能視為雲端拒絕。

依 [Kimi K3 官方模型頁](https://ollama.com/library/kimi-k3)，本機 API 可直接以 `kimi-k3:cloud` 呼叫；[雲端使用與模型命名](https://docs.ollama.com/cloud)、[登入說明](https://docs.ollama.com/api/authentication)區分本機代理與直接雲端 API。新版不再查本機 `/api/tags` 作必要條件，只發出指定模型的一次 `/api/chat`，保留實際登入／模型／服務錯誤；不自動拉取或替換。

優先在能正常使用 Ollama 的 **WSL 終端機**執行（Node.js 20+，Ollama 本機 API 已啟動；雲端登入由屋主管理）：

```bash
node /root/workspace/houseDesignPrepare/scripts/review_c1f_with_ollama.cjs
```

也可沿用 Windows 的 Node。Ollama 本身不必裝在 Windows，只需能連到 WSL 的本機 API：

```powershell
node '\\wsl.localhost\Ubuntu\root\workspace\houseDesignPrepare\scripts\review_c1f_with_ollama.cjs'
```

加 `--preflight` 只核檔案，不發出模型請求。腳本不安裝、拉取／切換模型或登入，不讀金鑰；只把本文研究部分及 C 相關資料交給本機 Ollama 的指定雲端模型，不傳執行說明或整個 A／B 設計。結果保存在執行端的 TEMP／`/tmp`，不寫圖面；將結果路徑貼回，供 Codex 讀取並逐項反駁／核對。若實際回覆要求登入，在執行 Ollama 的 WSL 終端機由屋主執行 `ollama signin`；不要把登入連結、金鑰或憑證貼進專案或對話。
